# Report layout update

Replace the four files below in your existing project, then restart frontend/backend:
- backend/reports/generator.py
- backend/reports/build_template.py
- frontend/src/components/ReportBuilder.jsx
- frontend/src/index.css

The included template is regenerated by the existing download endpoint.
For a fresh frontend setup run npm ci, then npm run build (or npm run dev).
Use the existing backend setup and existing LibreOffice installation.

Changes: remove empty template control paragraphs; reserve space for headings,
notes and captions; preserve whole photos and aspect ratios; align row tops;
retain captions for five-photo and larger layouts; show every selected photo
in the preview. A4 preview is illustrative, Word/PDF remain the final layout.
Input, upload, crop tools, selection, sorting, APIs, database and export routes
are unchanged. Explicit user crops are still honored.

Verified: production frontend build; DOCX -> LibreOffice PDF with 0, 1, 2, 3,
4, 5, 6, 7 and 9 mixed portrait/landscape photos plus labels and a note.
Each tested group occupied one physical page; all photos and captions were
present, and photo bounds remained inside the page. This is not an unlimited
single-page guarantee: extremely long text or many photos may continue onto
additional pages, and dense layouts reduce image readability.

Dependency folders, git metadata, build output, and generated report caches
are excluded. Original application data/uploads are retained.
